# Retrospective: 4 L's

Period: one-hundred-first use of analyse, correcting external-control authority,
inventory and target applicability, 14 September 2026
Place: this repository

## Liked

- The review correction exposed a completeness hole that broad control classes
  had hidden.
- Current whole-file authority pins made every expected state traceable to a
  repository claim that can be resolved again.
- Deriving the 39 control and target relations from 22 individual controls
  made omissions and inapplicable additions independently observable.

## Learned

- A class such as security configuration helps navigation but cannot be the
  unit by which completeness is judged.
- Release and main rulesets remain distinct controls even when both protect the
  same candidate and release targets.
- Honest current authority needs a resolvable path, a current hash and a named
  claim; remembered conversation supplies none of those.
- Applicability needs both edges and exclusions. Extra checks against the wrong
  target do not compensate for a missing required relation.

## Lacked

- The first pass used repository-traced as prose where the proof needed
  repository-resolvable authority.
- It represented security and rulesets too coarsely to catch omission of one
  declared control within a class.
- It did not prove that both 0.0.2 targets were present or that every applicable
  control and target relation was accounted for.

## Longed for

- Analyse guidance could prompt an authority-resolution table whenever an
  expected state originates outside the proposed requirement.
- External-state analysis could routinely derive an applicability matrix from
  individual controls before acceptance criteria are written.
- The follow-on release-record requirement could consume the same control and
  target identities without coupling its per-release evidence to this pull
  request.
