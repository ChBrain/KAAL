# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the fortieth use of the architect skill, on
`architecture/a-task-names-its-people` (three seams: a handoff line, a
reader for two walls, a rule at three seats), 8 September 2026.
Place: this repository

## Liked

- The analyst's stand-in had already run the board, so the drawing began
  from a list of what the change reaches rather than from a guess: the
  closed contract that fixes the handoff's line order, the closed contract
  that fixes an orphan drawing's verdict, the runner pages.
- Pricing the three decisions was quick because each had a cost the tree
  had already named: one line being small, three texts to keep agreeing,
  nonsense passing a wall that reads presence.

## Learned

- One resolver for both walls is the seam, not the line. The first
  stand-in read the People line beside the contract test and every drawing
  in the league went red; the fix was to say once where a test's
  requirement lives, and the verdict order followed from a closed contract
  rather than from taste.
- A house convention is a fixed thing even when no test reads it. The
  skill's sections are numbered; an unnumbered section passed every test
  and still read as a foreign body, so the drawing numbered it and moved
  two headings.
- The contract on a section's place is written against titles, not
  numbers, and the number is asserted once, separately. That is what let
  the analyst's test and the contract read the same heading differently
  without either being wrong.

## Lacked

- No word in the skill for a drawing whose build touches every requirement
  in the tree. Structure has "what changes", and sixty-four files is a
  class of change the template does not expect a drawing to name.
- Nothing about the generated pages a text change invalidates. The runner
  pages carry each skill's sha, so any drawing that touches a skill owes
  their regeneration, and the skill does not say so.

## Longed for

- A mechanism for text shared between skills, so a rule that belongs to
  every seat is written once and stamped, the way shared scripts are.
