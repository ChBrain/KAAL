# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the sixty-sixth use of the analyse skill, re-specifying
`a-diff-carries-one-seat` after its first drawing was closed unbuilt, on the
ask "branch scoped lanes, deny by default, no section exemption", 9 September 2026.
Place: this repository

## Liked

- Three of the six things that moved had already been measured. The old
  criteria said a path no seat owns is free and that a build may write its own
  requirement's Handoff, and both were true when they were written. What made
  them wrong was a field being deleted and a directory count that anybody can
  repeat, so the re-specification argues from runs and not from taste.
- The stand-in found the defect it exists to find, on the first pass and in
  the one test I would have shipped. Six of seven passed and the seventh
  counted the lane's own line as a seat, because the lane line names its
  seat too. That is a criterion missing a format, not a test being clumsy,
  and the criterion now says what a seat's line looks like.
- Running each of the seven alone as well as together took one loop and
  showed each red on its own missing thing. Four are red on the command, two
  on the config and one on the gate, which is what the Handoff claims and
  now what a reader can check.

## Learned

- A guard that reads its lane off the diff has no lane. The first
  specification said "the lane is read off the diff", which is `AGENTS.md`'s
  own sentence, and it means whatever you changed is what you meant to
  change. There is nothing left to be wrong about. The branch is the one
  declaration a person makes before the work, which is the only kind a guard
  can hold anybody to.
- Allow by default is the vacuous pass wearing a config. The old criterion 1
  said a path owned by no seat is not a finding, which sounds careful and
  means that every path nobody remembered to declare is free forever. This
  league has spent a week finding passes that could not fail, and one of them
  was sitting in a criterion I wrote.
- Two of the twenty commits I measured cross a seat because a tool wrote a
  number. `kaal traces --write` rewrites the suite count in the tester's
  plans, so every specify and every draw now moves a file in somebody else's
  directory without a person deciding to. A guard reading paths alone cannot
  tell that from an edit, and it is in the open questions rather than
  assumed away.
- Deleting a field made a criterion pointless four tasks later, and nothing
  connected the two. The section exemption existed because the board refused
  an open task whose tests were green; that refusal went when delivery became
  a report. Nobody noticed, because the requirement holding the exemption was
  not the requirement that changed.

## Lacked

- No name for a re-specification. This is not a supersede, because nothing
  closed and no drawing pins these criteria, and it is not an amendment in
  the usual sense either, because three criteria changed meaning rather than
  wording. I wrote a Handoff line called "Amended, not superseded" and
  invented it on the spot.
- Nothing tells an analyst that a task they wrote has gone stale because
  another task landed. The trace wall pins what a drawing read, so a moved
  requirement is caught. A requirement made pointless by a change elsewhere
  is caught by somebody remembering.

## Longed for

- A criterion that names an output line should be checkable against the line
  before anything is built. Criterion 2 fixes a format now because the
  stand-in caught it, and the stand-in is the only place in this method where
  that happens at all.
- The open question about where a build's own record goes belongs to a task
  that already exists and is undrawn. Pointing one requirement's open
  question at another task by name is the closest this tree has to saying
  "not mine, theirs", and there is no line in the template for it.
