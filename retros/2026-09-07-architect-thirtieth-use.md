# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the thirtieth use of the architect skill, drawing both tasks of
one analyst run, `red-for-the-right-reason` and
`what-a-closed-task-fixes`, six seams over one skill file and one archive
move, 7 September 2026.
Place: this repository

## Liked

- Placing each rule where it is met rather than where it is about. The
  reading rule goes in the section a writer reads before the first
  criterion exists; the supersede rule goes in the handoff. Both are
  decisions with a reason, and both would have read tidily in one place
  and worked worse there.
- Drawing the archive move as a seam. The promise is not that files moved,
  it is that moving them changed no count, because consumption is by name.
  If it were ever by location, a move would silently reset a stack.

## Learned

- I wrote a guard against disturbing a closed task's sentence and put the
  guard in the wrong section: `analyse-v3`'s red run sentence lives in the
  proof, not in the handoff, and I asserted it from memory. The guard
  failed, which is the right outcome, but it failed as a defect in my test
  rather than as a finding about the change.
- The stand-in caught a phrase I had fixed in my own drawing and then
  typed differently while writing the text: "from the run and never from
  the plan" against the fixed "from the run, never from the plan". The
  Fixed section exists precisely for that, and I still drifted from it in
  the same hour I wrote it.

## Lacked

- Nothing in the skill says how to draw two tasks from one run without
  repeating the parts they share. Both drawings carry the same third seam,
  worded twice, and if one changes the other will not.
- No help on asserting that a closed task's sentence is undisturbed. It is
  the right instinct and it needs to know where the sentence actually is,
  which means reading it rather than remembering it, which is the very
  lesson one of these two tasks is about.

## Longed for

- A way for two drawings from one run to share a seam, so a promise they
  both hold is written once and tested once.
