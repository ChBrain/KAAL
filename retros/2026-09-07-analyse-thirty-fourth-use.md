# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the thirty-fourth use of the analyse skill, an analyst run over
twelve unconsumed retros of that same skill, producing
`red-for-the-right-reason` and `what-a-closed-task-fixes`, 7 September 2026.
Place: this repository

## Liked

- Half the stack says "Lacked: nothing new". Six consecutive uses in which
  the skill was not the constraint is the loop working, and it made the
  run short: the material was in four retros, not twelve.
- Two Lacked items had already been answered between the retro and this
  run, by a task the run itself had caused. Recording that in the
  assumptions rather than writing the criterion a second time.

## Learned

- The stack's strongest signal was not a Lacked at all. Three seats on one
  day asked for the same reading, which closed tests name a path I am
  about to change, and that is tooling rather than skill text, so it
  cannot be a criterion for this skill and went to the open questions of
  both tasks. A stack can shout something the skill it feeds cannot fix.
- Splitting the stack into two tasks was the right shape, and I reached it
  by noticing the items answered two different questions: how to prove my
  own criteria, and what another task's closed work fixes. The count came
  from the material, not from a rule.

## Lacked

- Nothing says how to split a stack, or how many tasks a run may produce.
  The precedent is a run that wrote three; I wrote two; both were
  judgement with nothing behind them.
- The ten-retro rule counts per skill and says nothing about a stack whose
  items belong to different subjects. It says when to run, never what a
  run's output looks like.

## Longed for

- A way to mark a Lacked item as answered elsewhere, so the next run over
  a stack does not have to rediscover that it was.
