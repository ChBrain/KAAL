# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the thirty-fifth use of the analyse skill, an analyst run over
twenty one retros, ten of the architect skill and eleven of the code
skill, producing three tasks, 7 September 2026.
Place: this repository

## Liked

- The loudest signal was unmistakable and needed no interpretation. Four
  code retros in two days say the same thing: the skill reads as though
  every build has source. A stack that repeats itself is the easiest kind
  to act on and the hardest to argue with.
- Nine of the twenty one say "Lacked: nothing new", which is what a
  healthy loop looks like from the inside.

## Learned

- Two of the three tasks are lessons already written an hour earlier for
  another seat. The architect's green contract test and the analyst's red
  run are one idea; the architect reading the closed tests and the
  analyst reading them are the same sentence in two files. A lesson found
  in one seat is usually owed to all of them.
- I noticed that by remembering, not by any rule. The loop feeds each
  retro to the skill it names, and nothing in it can say that a finding
  belongs to every seat.

- A requirement that names its consumed retros in prose does not consume
  them. The stack still read ten for the code skill after the run, because
  the reader matches filenames and I had written "the code retros of the
  twenty-first through the twenty-eighth use". The tool caught what I had
  not.

## Lacked

- Nothing tells an analyst that a stack for one skill may carry a lesson
  every skill needs. I have now written the same criterion into three
  skills across two runs, by hand, and the only thing stopping the fourth
  from being missed is that I was in the room for all of them.
- No guidance on how to name a task that is another task's twin at a
  different seat. Three of the names in this run were chosen to sound
  unlike names I had used that morning, which is not a reason.

## Longed for

- A place for a rule that belongs to every seat, written once, with each
  skill pointing at it, so a lesson found in one seat does not have to be
  copied into five by whoever happens to notice.
