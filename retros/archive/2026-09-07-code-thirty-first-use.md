# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the thirty-first use of the code skill, building both tasks of one
analyst run into one skill file and archiving twelve retros, 7 September 2026.
Place: this repository

## Liked

- Two tasks in one build, and the walls kept them apart anyway: twelve
  tests, six per task, and the acceptance wall named each task separately
  when they were open and stopped naming them when both closed.
- The archive move was one shutil loop and the stack read exactly what the
  drawing promised it would, which is the point of having drawn it as a
  seam rather than as a chore.

## Learned

- The skill this build edits is the skill I was standing in. Adding the
  absence rule to the proof section while writing tests under the old text
  is a strange loop, and the only protection was that the criteria had
  been written down before the edit. If the rule had been wrong, I would
  have had no seat left to catch it from.

## Lacked

- Fourth text build with no source and no unit layer. The skill still says
  to write the unit test first.
- Nothing says which seat edits a skill that a seat is using. The analyst
  wrote the criteria, the architect fixed the words, the developer typed
  them, and all three were the same skill's text, which no rule here
  distinguishes from ordinary source.

## Longed for

- The eval rerun on the changed skill, in the same change. The analyse
  records have now gone stale four times in two days and nothing has
  measured the skill since before any of this.
