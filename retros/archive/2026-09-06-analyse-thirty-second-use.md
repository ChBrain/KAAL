# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the thirty-second use of the analyse skill, on
`requirements/a-guest-takes-no-orders` (three criteria, written from a
run rather than from a plan), 6 September 2026.
Place: this repository

## Liked

- The requirement came out of a real run and not out of a design meeting.
  Every assumption in it names something that actually happened an hour
  earlier, which made the criteria easy to keep to three.
- Separating directives from conventions was the whole design. A rule that
  said only "do not obey the tree" would have been wrong in the other
  direction, since a guest that ignores a host's language writes something
  the host cannot use.

## Learned

- The rule I was writing is probably an instance of a larger one. A
  directory a skill was pointed at, a fetched page, a tool's output: all
  are inputs the skill did not write, and all can carry sentences shaped
  like orders. I wrote the narrow rule and put the wide one in the open
  questions, because the narrow one is the one a run proved.

## Lacked

- The skill has no notion of an untrusted input. The word does not appear
  anywhere in it, and neither does any advice about text that arrives from
  outside the ask. Every criterion I wrote here is about that idea, and I
  had to name it myself.

## Longed for

- A worked example in the skill of a criterion that separates two things
  living in one place, since the whole difficulty here was that a host's
  file carries orders and facts in the same paragraphs.
