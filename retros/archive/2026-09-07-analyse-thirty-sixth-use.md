# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the thirty-sixth use of the analyse skill, on
`requirements/the-surface-is-written-down` (four criteria, the first of
four tasks toward a version), 7 September 2026.
Place: this repository

## Liked

- The ask contained its own ordering once its constraint was read. "You do
  not touch minor or major" means the class of a change must be refusable
  by a machine, and nothing refuses a change without a surface to judge it
  against, so the page comes before the wall. I had proposed the reverse an
  hour earlier and said so.
- The task decides nothing. Every promise on the page was already fixed by
  a closed requirement; this only gathers them, which made the assumptions
  short and the open questions honest.

## Learned

- A page and a command's usage line are two readings of one fact, and the
  repository already had that pattern: `evals/README.md` and the record's
  fields are held equal by a test. Reaching for a pattern the tree already
  uses cost nothing and gave criterion 4 its shape.
- Writing a criterion about a page's headings meant deciding what counts as
  a command name in prose. The test reads the usage line for the list
  rather than carrying one, which is the count lesson from this morning
  applied to something that is not a count.

## Lacked

- Nothing in the skill helps with a task whose whole content is
  transcription. Its steps assume something can fail in the world; here the
  only thing that can fail is a disagreement between two documents, and I
  had to invent the failure to have criteria at all.
- No guidance on a task that exists to unblock three others. The handoff
  has `Blocked on:` for what this task waits for and nothing for what waits
  on it, so the ordering lives in a pull request body and nowhere the tree
  can read.

## Longed for

- A way for a requirement to name what it unblocks, so a reader of the
  tree can see an order that today only exists in a conversation.
