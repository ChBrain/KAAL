# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the twenty-sixth use of the analyse skill, on
`requirements/applies-here` (a command says when its question does not
apply to the tree it was pointed at), 6 September 2026.

## Liked

- The ask came from an argument I had lost. I had said the difference
  between the two modes was too small in the code to name; pointing the
  commands at a plain directory answered that in three lines, an invented
  finding and two vacuous passes. The requirement quotes the run rather
  than the argument.
- One rule, five instances, three criteria. The five commands are a list
  in the test with its count asserted first, so a sixth command added to
  the list without its build is red rather than quietly unchecked.

## Learned

- Reading the closed requirements before writing criteria, which the
  architect skill now demands of its seat, is worth the same minute to
  the analyst: five closed tasks fix these commands on their fixture
  roots, and every one of those roots holds what its command reads. That
  is what made per command applicability safe, and a root level adoption
  marker unsafe, since the fixture roots are not adopted trees.

## Lacked

- Nothing new.

## Longed for

- The skills side of the same ask: the six seats saying they act inside a
  repository that adopted the league, and assessment as a seventh seat.
  A script can be told its mode by an argument; a skill can only be told
  by its own text.
