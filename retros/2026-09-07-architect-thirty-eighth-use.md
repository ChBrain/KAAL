# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the thirty-eighth use of the architect skill, on
`architecture/each-skill-carries-its-own-version` (three seams, a rule, six
frontmatter blocks and a sentence), 7 September 2026.
Place: this repository

## Liked

- The price line landed the same day it was built and it changed two
  records. The one about refusing a version's shape as well as its absence
  reads as obviously right until you have to say what it spends, which is a
  rule that will be in the way the day a skill earns a minor bump. The one
  about the wall not comparing a version to a change spends the guarantee
  in Kai's own words, "each skill moves on its own", and saying so is
  better than letting the split look free.
- Contract 2 asserts that nothing but the version is reported. The analyst
  found her fixture tripping the fixtures rule, and the cheapest way to
  stop that recurring was a test that fails when the fixture breaks a rule
  it is not testing, rather than a comment asking the next person to be
  careful.

## Learned

- A split ask leaves a hole and the record is where it goes. This task and
  the next are two halves of one sentence Kai wrote, and after this one
  lands a skill can change without its version moving and nothing notices.
  That is a real gap, it is not a defect, and the only honest place for it
  was the `Bought:` line of the decision that made the split.
- Three cases of one rule are one seam, not three. The strategy table has
  criteria 2 and 3 both served by contract 2, because they are the same
  command answering about the same key; splitting them would have made two
  tests that build the same fixture and read the same line.

## Lacked

- Nothing helps decide whether a rule that constrains a value should also
  constrain its shape. The requirement asked for a version; I drew a wall
  that refuses four kinds of wrong version, which is more than the ask and
  traces to a constraint rather than a criterion. The skill says everything
  drawn must trace to a criterion or a constraint and does not say how far
  a constraint may stretch.
- The template still has nowhere for a fact established by running
  something. Sixth task in a row, and this time the fact is that YAML reads
  an unquoted 0.1 as a number, which is why the contract requires quotes.

## Longed for

- A way for a drawing to name the task that closes the gap its own decision
  opened, so a reader of this record can find the other half without
  reading a pull request body.
