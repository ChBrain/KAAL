# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the seventy-second use of the architect skill, reading a criterion
that stopped fixing where a test lives, 12 September 2026.
Place: this repository

## Liked

- The read was one line and the answer was that nothing here is about it. This
  drawing draws the ledger, the record and the workflow, and owns no seam
  about where a test file sits, so a criterion that stopped naming a directory
  reaches nothing it holds.
- It did not take the promotion to zero and I expected it to. The pin is
  clear and the task still reads `not delivered`, because the criteria moving
  moved the suite too and the record now names a sha the suite no longer has.
  Expecting the read to be the last thing was a guess, and running the
  promotion afterwards is what corrected it.

## Learned

- A pin over a criteria region is a pin over every clause in it. What moved
  was one criterion's two clauses about scripts and test homes, and the pin
  cannot say which part moved, so the read has to say why neither reaches
  here rather than why the change was harmless.
- The same shape, a third time in two days: an analyst diff moves a criteria
  region, a drawing pins that region, and nothing else in the analyst's chain
  can clear it. The architect is pulled in for a sentence each time, and each
  time the task sits `not delivered` until it happens.

## Lacked

- Any way to tell a criterion that touches a drawing from one that does not,
  before opening the drawing. The pin fires the same either way.
- A way to see everything one task still owes, in one answer. The pin was
  clear and the record was stale and those are two commands, so a seat that
  ran the first and stopped would have handed over a task it thought was
  finished.

## Longed for

- A pin per criterion rather than per region. Three of the four reads I have
  written over two days said the same thing: the criterion that moved is not
  one this drawing answers.
