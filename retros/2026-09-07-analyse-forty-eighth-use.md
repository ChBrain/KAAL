# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the forty-eighth use of the analyse skill, on
`requirements/a-retro-names-what-it-read`, written from a question rather
than from a stack, 7 September 2026.
Place: this repository

## Liked

- The section added an hour ago earned itself on its first use. Six facts
  went under What the runs said that would otherwise have been assumptions,
  and one of them, ten closed tests reading the count line anchored, turned
  out to be the constraint that decides the whole shape of the change. Found
  by running a search rather than by remembering, and on the page where a
  reader can rerun it.
- The ask was a question and the honest answer was smaller than the
  question. Kai asked whether the league needs more skills; the counts say
  it needs a feedback loop for the three it already has and cannot hear
  from. Writing the smaller half as a requirement and leaving the seat
  question for evidence is the answer, not a deferral of it.

## Learned

- A report line is a seam and it took a run to see it. Adding a second
  number to `<skill>: <n> unconsumed` would have broken ten closed contracts
  across two walls, all of them anchored on the end of that line. The
  cheapest change on the page was the most expensive change in the tree, and
  the only reason it did not get written that way is that the count came
  before the criterion.
- Three criteria rest on one promise and no single break separates them.
  Criteria 2, 3 and 5 all read the read line's shape, so breaking the line
  reddens all three. Two isolations still separated their reasons, the count
  and the consumed read, and the third is genuinely one promise. That is
  what the rule added this morning asks a run to notice, and it is the first
  time it was noticed rather than assumed.
- An isolation that breaks the code rather than the behaviour tells you
  nothing and looks like a finding. One attempt left a dangling expression,
  every test went red, and for a moment that read as five tests sharing a
  precondition. An isolation is only evidence when the tree it makes still
  runs.

## Lacked

- The skill has no rule for a criterion on a line another test already
  reads. The requirement fixes a command's output format, which section 2
  already asks for, but nothing tells the analyst to go and count who reads
  the old format first, and that count is what decided this task's shape.
- Nothing says what a requirement written from a question rather than a
  stack must carry. This one names the question and the half it answers,
  because leaving that out would make the deferred half look forgotten, and
  no rule asked for it.

## Longed for

- A way to ask the tree who reads a line before changing it. The answer here
  came from a grep over two directories and a human reading ten files, and
  the same question arrives with every format this league fixes.
