# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the ninety-eighth use of the analyse skill, stating that retro-4ls
counts what it feeds, 14 September 2026.
Place: this repository

## Liked

- Discovering the executable through the move record keeps the proof on the
  skill surface and makes the present absence the exact red.
- Small roots isolate top-level, archive, consumption, grammar, read and zero
  behaviour without borrowing the league's changing retro stack.
- The disposable copied-skill stand-in made all ten cases green together and
  alone, so the common missing move is not hiding tests that cannot pass.

## Learned

- The old authority is split across a requirement and a drawing. The
  `push-v1` criterion promises the command, while its drawing assigns the
  counting algorithm to `bin/lib/retros.mjs`; preserving the first does not
  require preserving the second.
- A copied-skill proof has to copy the whole skill before execution. Pointing
  the original script at an engine-free fixture root would still allow a
  relative import back into KAAL and would not prove independence.
- A count described as current is still a dated observation. The manager's
  first retro landed while this branch was in flight, so zero belongs on
  fixed ground and not in a test of the moving league tree.

## Lacked

- A requirement trace state for an authority that is in tension but whose
  exact supersede depends on the architect's integration decision. The page
  can name it, but `supersedes:` can only honestly say `nothing` until the
  moved claim is fixed.

## Longed for

- A standard acceptance helper for resolving a scripted move from a skill's
  ledger and exercising a copied skill without its source repository.
