# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the third use of the manage skill, correcting the live release
orientation and bootstrapping the common lifecycle, 14 September 2026.
Place: this repository

## Liked

- Verifying the remote ref before judging the board corrected a stale release
  premise.
- An empty initialization commit made the draft pull request exist before
  substantive Manager work.
- The provisional backlog claim preserved the existing block grammar while
  making this Manager cycle visible.

## Learned

- Empty block maps do not establish that no Manager plan action is justified.
- The backlog reader's exact answer is that nothing is clear yet, not that
  nothing needs management.
- A common lifecycle requirement can be accepted for a release before its
  implementation shape is admitted.
- Active rulesets and a completed red CI run make promotion truth observable
  without relying on the release plan's older prose.

## Lacked

- One executable shared lifecycle that creates and checks the draft, claim,
  proof, retro, reconciliation and ready transition.
- A persistent claim representation that does not require a provisional
  Markdown section.
- A retro naming surface that continues beyond the ninety-ninth use of a
  skill.

## Longed for

- One portable `pdca` skill that every seat uses without copying the cycle
  into seven skills.
- A Manager view derived from durable live claims and blocks rather than pull
  request prose.
