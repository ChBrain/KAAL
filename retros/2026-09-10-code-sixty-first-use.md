# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the sixty first use of the code skill, building
`an-install-carries-the-method`: the command that puts the league into a
consumer's tree, 10 September 2026.
Place: this repository

## Liked

- The applicability entry asks the module rather than copying its rule.
  `assemble` refuses a tree with no skills in exactly one place, and the table
  reads that answer, the way `boundary` reads the wall's own list of places
  rather than a copy. Two answers to one question is one of them wrong the
  day the other moves, and this tree had already written that down.
- The drawing said `SURFACE.md` was owed with the build, and the surface wall
  said so too, by name, within a minute of the command existing. Two seats
  agreeing about an obligation without either reading the other is the chain
  working rather than a coincidence.
- Proving both halves together before splitting them. The build alone leaves
  the suite red, because the manifest is governance's, so I made both changes,
  watched all six criteria go green, then put the governance half back and
  landed the build knowing exactly what the other diff owes.

## Learned

- `assemble` is the first guarded command that judges the tree it is standing
  in rather than one it was handed, and it took reading `runner` and `release`
  to see that the table already had that shape for two others. Its first
  argument is where a consumer wants the league, not where it is, so reading
  the destination as a root would have refused for the wrong reason and named
  a directory that does not exist yet.
- The package direction is the opposite of every other command's. Fourteen of
  them read a tree and answer about it; this one reads the tree it is in and
  writes into another. That asymmetry is why the guest rule matters here and
  nowhere else in `bin/`, and why the seam that decides where a file may land
  is worth a seam of its own rather than a line inside the copy.
- Splitting by lane made the release two diffs and the split is the honest
  one. The command is the developer's, the manifest and the page are
  governance's, and neither diff alone makes a criterion true. A build that
  cannot go green on its own is not a broken build; it is a task whose proof
  spans two seats, and the four verdicts already have a word for that.

## Lacked

- Nothing says a task's criteria are satisfied by two diffs together. The
  acceptance wall reads one tree at one moment, so the build reads `not
delivered` for a reason that is true and useless, and the only place the
  pairing is written down is a drawing's Handoff and a plan's item.
- No way to run the acceptance suite against a tree assembled from two
  branches. I did it by making both changes and then undoing half, which
  works and is not a thing a wall could check.

## Longed for

- A cheap check that `files` ships what a criterion says it must. Criteria one
  and two are proved by packing a tarball and unpacking it, which is the
  slowest thing in the acceptance wall, and what they actually compare is a
  manifest against a directory listing.
- The scratch tree helper, fifth record. This build wrote a package fixture by
  hand again, and the contracts, the acceptance tests and two other suites now
  all carry their own copy of nearly the same twenty lines.
