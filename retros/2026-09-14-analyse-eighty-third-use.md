# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the eighty-third use of the analyse skill, stating
`a-seat-names-what-may-block-it` after the asker gave the eight edges of the
dependency flow between seats, 14 September 2026.
Place: this repository

## Liked

- The ask counted to two and the second one could be named exactly. "Define
  and enforce" split on a fact rather than on taste: enforcing needs a live
  block to judge, nothing in this tree records one, and the manager's plan
  already orders that record behind two unbuilt items. So the second task has
  a name, a reason it cannot be stated yet, and a place in somebody's order.
- Reading the manager's plan before the tree paid twice. It carried the same
  table in prose, said where it belongs, and disagreed with the ask on exactly
  one row. Finding a contradiction between the ask and the backlog is worth
  more than any criterion this page carries.
- The four mutations. The stand-in went green first time, which says nothing
  on its own, and breaking it four ways is what turned that into evidence.

## Learned

- A stand-in that goes green first time is the weakest kind of stand-in. The
  skill's rule is that a stand-in finds tests red for the wrong reason, and
  the first use of it found three; here it found none, and a green run over
  seven tests is exactly as consistent with seven vacuous tests as with seven
  good ones. Mutating it was not in the method and it is what made the run
  mean something.
- A shared red can be the honest one. Four of the seven were red on one
  missing command, which the skill warns about, and splitting them would have
  meant inventing four surfaces for one. The rule is about a shared
  precondition hiding how many proofs it holds up; where the precondition is
  the whole subject of the criteria, the count is real and the stand-in is the
  only way to tell.
- An analyst diff carries a line in the tester's tree now. Adding a
  requirement adds an acceptance case, a case no suite names is a finding, and
  it reddens three closed suites on one line. `tests/suites/*.md` is shared, so
  the lane takes it, and the shape is new since `a-suite-names-its-cases`
  landed three days ago.

## Lacked

- Nothing in the skill about an ask that is partly unstateable. The rule for
  counting an ask is about tasks that can fail independently, and it says
  nothing about a task that cannot be written at all because the thing it
  would judge does not exist. Naming it, saying why, and handing it to the
  backlog was the right shape and it was invented here.
- Nothing about reading the manager's plan. The skill says to read the closed
  requirements whose paths the task touches; it does not say to read the
  order the work sits in, and the order is where the contradiction was.
- No rule for mutating a stand-in, which is the paragraph above.

## Longed for

- A way to say "this criterion holds until the answer to open question 1
  arrives". The ninth edge is one line in a declaration and the page carries
  it as prose in three places; nothing in the tree connects an open question
  to the criterion that would move if it were answered.
