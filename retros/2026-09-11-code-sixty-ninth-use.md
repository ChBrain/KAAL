# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the sixty-ninth use of the code skill, building the promotion,
11 September 2026.
Place: this repository

## Liked

- Nine seams, one new module of a hundred lines and one of twenty, and every
  answer it gives comes from a function that already existed. The drawing said
  this would be small and it was.
- The build order the drawing suggested was abandoned on purpose and said so.
  A head wall without the verdict gates is a gate that passes what it exists
  to refuse, and a half built gate behind a branch protection is worse than no
  gate at all.

## Learned

- A board that guessed its target judged a fixture by its parent. Reading the
  refs the tree holds meant a scratch tree inside this clone inherited this
  clone's `origin/release` and was judged leniently for having a parent, and
  `waiver-v1` went green on a red board. The board is told its target now, and
  no answer is the strict answer. That is the third thing this week that was
  wrong because it read what was lying around rather than what it was given.
- The hook is not the developer's. Teaching it to say where a push is going is
  four lines of shell in `.githooks/`, which is governance, and the seats wall
  refused the diff carrying both. So the desk stays strict until that lands,
  and criterion 9 is green in the tree and not yet true on a machine.
- A unit written to document a kindness found the kindness missing. `--into
origin/main` was refused while `KAAL_BASE=origin/main` was read, for no
  reason except that one went through the stripping and the other did not.

## Lacked

- A way to try the promotion against `main` without a promotion. The only
  honest rehearsal is the first one.

## Longed for

- One board run per gate. The promotion runs the walls and the gate it sits in
  runs them too, which is a decision with a recorded reason and still two
  minutes twice.
