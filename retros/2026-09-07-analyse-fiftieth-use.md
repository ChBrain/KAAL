# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the fiftieth use of the analyse skill, on
`requirements/a-build-says-what-it-proved`, a run over a stack of thirteen,
the third stack read today, 7 September 2026.
Place: this repository

## Liked

- Every criterion came out of the same seat asking the same thing three
  ways. The change class appears in three retros, a proof completing
  somewhere else in three, and each time the seat had the fact in hand and
  no place to put it. Nothing here asks anyone to know more than they
  already did, only to write it where the next reader looks.
- Two of the thirteen name defects rather than gaps, and both earned their
  own criterion. Correcting a record in place appears once and in both
  Lacked and Longed for; a supersede the analyst did not name appears once
  and says plainly what would have happened had a wall not caught it.
- The oldest item in the stack is now buildable. Three retros asked for the
  change class in the handoff while `kaal class` did not exist. It exists,
  and the criterion that was impossible when it was first asked for is the
  cheapest one here.

## Learned

- A fold and a full stop are not a sentence. Splitting the whole skill on
  periods makes one pseudo sentence of every heading and every fenced block,
  and three assertions were green against text three sections away because
  of it. A paragraph inside a named section is what a rule actually lives
  in, and reading that is what made three isolations bite. Fifth time this
  week the same shape, and the stack itself asks for the helper that ends it.
- An isolation that reddens nothing is a question and twice today the answer
  was the isolation. Removing a sentence from a two sentence rule leaves the
  rule stated; removing the sentence that introduces a block leaves the
  block. Both looked like weak tests and both were weak breaks, and the only
  way to tell was to break the whole thing and then each part.
- A script that writes its file once at the end loses every edit it made
  before the assertion that threw. Three test rewrites vanished silently and
  the run afterwards was green, which read as success. The edits are written
  as they are made now.

## Lacked

- The skill says a criterion on a command's output fixes that line's format,
  and says nothing about a criterion on a document's shape. Criterion 1 here
  fixes a handoff as named lines, which is the same kind of promise about
  the same kind of artefact, and it had no rule to be written under.
- Three stacks in one day and nothing says whether that is fine. The rule
  fires per skill at ten and two skills crossed the line within an hour of
  each other twice today. Nothing about pacing, and nothing about a stack
  read while its own skill is being changed by another task in flight.

## Longed for

- A count of how many criteria in a stack run came from one retro versus
  several, in the requirement itself, so a reader can see which parts of the
  next version rest on a pattern and which rest on one seat's bad afternoon.
