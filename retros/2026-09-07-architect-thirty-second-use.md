# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the thirty-second use of the architect skill, drawing all three
tasks of one analyst run, eight seams across two skill files and one
archive move, 7 September 2026.
Place: this repository

## Liked

- Placing each rule where a reader meets it, again, and having a reason
  for every placement rather than a habit. The no-source case belongs
  where a build begins; the green contract case belongs beside the
  sentence it contradicts; the runner rule belongs with the other rules a
  contract must meet.
- Writing the runner rule for any repository rather than for this one. It
  would have read plainly with this league's wall named in it, and it
  would have been useless to anyone else.

## Learned

- The same promise is worded three times in this run, once per drawing:
  that archiving changes no count. Three wordings of one promise is three
  chances to drift, and the thirtieth use asked for a way to share a seam.
  Naming the duplication in each drawing is the least I could do and it is
  not a fix.
- A drawing that leaves the count to be computed by the test is the same
  lesson as the one I had to repair on main an hour earlier. It is easier
  to see a brittle assertion in someone else's test than in the one you
  are about to write.

## Lacked

- The skill has no advice on drawing three tasks at once. Everything it
  says assumes one requirement, one drawing, one set of seams, and a run
  that produces three leaves the architect deciding alone what may be
  shared and what must be repeated.
- No guidance on how a drawing should treat a duplication it can see and
  cannot remove.

## Longed for

- The shared seam, again: one promise, one wording, one test, referenced
  by every drawing of a run that holds it.
