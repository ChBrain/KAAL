# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the ninety-second use of the analyse skill, stating that a refusal
names whose path it reached, 13 September 2026.
Place: this repository

## Liked

- The measurement found the whole task before a criterion was written. One
  scratch tree, one crossing, and the answer showed the owner computed one
  line above the finding and thrown away, which is what the asker's item says
  and is now a run anybody can repeat rather than a claim.
- The stand-in ran the layer above and the closed tasks came back green. This
  task widens a string three closed criteria read, and knowing that before
  the architect sees the page is the difference between a supersede and a
  sentence.

## Learned

- **Two of five criteria passed before anything was built, and both were
  about absence.** One asked that a finding name no seat for a path nobody
  owns, which is what silence already does. The other asked that nothing be
  said where nothing was refused, which cannot fail while nothing says
  anything. The skill's rule about a witness was followed in both and neither
  was saved by it: a witness proves the run happened, and it does not make an
  absence criterion able to fail.
- The fix for each was to give the absence a subject. The first now asks the
  finding to say no seat owns it, in words, so a reader can tell a path
  nobody owns from a path whose owner the wall forgot to name. The second now
  asks that the refused path get the owner and the allowed path in the same
  diff get nothing, which is the same guard with something to compare.
- Adding one case moved two plans, and the measurement in the asker's item 6
  predicted the number. The acceptance suite gained a line, its sha moved, and
  both the acceptance plan and the regression plan read `review-needed`
  because both name that suite. Paid once, by hand, exactly as the item says
  the analyst pays it per task.

## Lacked

- Anything that tells a criterion about absence from a criterion that cannot
  fail. The count script checks that criteria and tests are equal and the
  red run checks the total, so five tests failing hid nothing, but two of
  them passing was visible only by reading the per test result.

## Longed for

- A red run that says which criteria passed. The command already prints it
  and the handoff records a count, and a handoff that said `5 failing` where
  three were failing would have read the same way.
