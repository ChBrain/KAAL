# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the fifty-eighth use of the analyse skill, on
`requirements/the-engine-installs-by-name`, from Kai's ask to release the
engine under his scope, 8 September 2026.
Place: this repository

## Liked

- Reading the consumer's thirteen packages before writing a criterion. The
  scope, the registry and the two access values were facts in five seconds
  and they decided the whole shape; guessing at any of them would have
  produced a task about npm rather than a task about this league.
- The task found its own second supersede before the drawing did. Adding
  `packages: write` meets a claim this session narrowed four hours ago,
  which required a reason only on `contents: write`. The narrowing was
  right for the write in front of it and wrong for the next one, and the
  next one arrived the same day.

## Learned

- `private: true` was the only thing stopping a publish, and removing it is
  removing a guard. The replacement is named in an assumption rather than
  left implied: a scoped name and a declared registry, so a publish that
  reaches the wrong place has to be asked for twice. A build that deletes a
  guarantee and says nothing is the shape a code retro named in August.
- An isolation that reddened nothing showed the stand-in carrying something
  decorative. The publish step set `npm_config_tag_version`, which is an
  input to `npm version` and not to `npm publish`, so removing it changed
  nothing and the test still passed because its window bled into the tag
  step above. Both the line and the assertion are gone: the manifest decides
  the version and the refusal has already checked it.
- A rule stated in a bullet's title is stated. Removing the body sentence
  left the title carrying the whole rule, so the isolation that mattered was
  the one that took the title too. Twelfth time this week that a test read a
  region wider than the rule it was about.

## Lacked

- Nothing says what a task owes when it changes what the artefact is. This
  one turns a git ref into a published package, which makes a sentence the
  operate skill gained yesterday true of one case and silent about the
  other. The skill has no rule for its own rules meeting a new case.
- The tree has three pages that describe it and nothing reads any of them
  against it. `SURFACE.md` was stale for a day after the read count landed;
  `DESIGN.md` still opens by saying nothing here is implemented, on a tree
  with eleven walls and a released version; and an outside review scored
  this repository from that sentence today.

## Longed for

- A wall that reads a page against the tree it describes: the exit codes a
  command can produce, the walls the board runs, whether the thing the page
  calls unimplemented has tests. Three stale pages in one day is a pattern,
  and every one of them was found by a person rather than by the board.
