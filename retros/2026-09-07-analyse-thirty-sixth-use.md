# Retrospective: 4 L's

Self-diagnosis: drawn from session context. Not a human-reported retro.

Period: the thirty-sixth use of the analyse skill, its first step only:
reading and counting an ask that pointed the skill at a directory and
named a third repository for the work to land in, 7 September 2026. The
run ended in findings handed to the asker and not in a requirement,
because the direction for the third place had not yet been given in the
asker's own words and the count waits on them.
Place: a directory the skill was pointed at

## Liked

- The ask named all three places and their roles before the run began,
  so the question the skill opens with was already answered. Nothing was
  asked and nothing was written.
- Recording refs, stashes, configuration and hooks before the run took a
  minute and made the afterwards attributable, which the thirty-first use
  had lacked. The witness and the working tree hash both read unchanged.
- The commands that answer exit 2 on a root that adopted nothing turned
  the state of the landing place from a question into a fact in seconds.

## Learned

- Reading and counting the ask is the whole first day of a guest run, and
  the skill spends three sentences on it. The count could not be taken:
  a direction is not an ask, and the landing place turned out to hold
  content of another kind. A step that ends in one question to the asker
  is a legitimate end of a use.
- The tree's conventions were the largest single output: its own contract
  document, a ladder of three rungs where the league has four, a planning
  record in dated review files, and a house style built on the dash the
  league forbids. The skill says name them; it does not say in what shape.
- The witness reads the version control directory like any other. A fetch
  or a reflog write moves the manifest without a byte of the working tree
  moving; the pointed-elsewhere fixture avoids this by shipping no such
  directory, and a real project is a working copy, always.
- The file addressed to an agent was easy to find because it announced
  itself as the whole instruction. What the skill did not say to look
  for: the tree's ignore file recorded an earlier agent's mistake, a
  worktree committed by a blind add, which is evidence about how agents
  have already behaved there and belongs in the findings.

## Lacked

- No shape for a scouting output. The skill has a template for a
  requirement and none for findings handed back before one exists, and
  the ask had to supply the headings.
- No list of what to look for in a pointed-at tree. The ask supplied it
  (files addressed to agents, conventions that disagree with the league's,
  whether the tree is a working copy); the skill should carry its own.
- Nothing about a third place. The skill knows the league and the
  directory it was pointed at; this run had a landing place as well, and
  it was neither empty nor the kind of repository the skill expects.
- No rule for a proof that can only be read. The tree's own acceptance
  suite builds deliverables and compares them against its committed tree,
  so running it as a guest would have moved the tree. It was read and not
  run, and the skill gave no words for that standing.

## Longed for

- A witness that knows what a working copy is, or one sentence in the
  skill saying version control witnesses the working tree and the witness
  covers the rest.
- A findings template for a scout, short, with the three headings this
  ask used: what disagrees with the league's contract, what conventions to
  name, and what the landing place already holds.
