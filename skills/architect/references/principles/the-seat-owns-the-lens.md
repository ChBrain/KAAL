# The seat owns the lens

## The pull

**A cross cutting skill owns the method.** One skill says how a thing is
done, once, so every seat does it the same way and a reader moving between
seats meets one shape. It buys agreement: the method improves in one place
and everyone gets the improvement, and two seats reporting the same kind of
finding report it in the same words. It costs fit, because a method written
for everyone is written for nobody in particular, and the seat that needed
one more question does not get to ask it.

**The seat owns what the method is pointed at.** Only the seat knows what its
own work is made of, so the seat decides what the method looks for. It buys
usefulness: a retro that asks an architect about tensions and a developer
about seams finds things a shared list of questions never would. It costs
drift, because two seats pointing the same method at different things will,
given time, stop meaning the same thing by it.

## Which side a case is on

Ask whether the thing being decided is how or at what. How a retro is
structured, what a finding line looks like, when a check runs: that is
method, and it belongs to the skill that owns it. What a retro asks about,
which tensions count, what a seat's own work is made of: that is the lens,
and it belongs to the seat.

Ask who would notice if it were wrong. If a reader of any seat would notice,
it is method. If only the people doing this one kind of work would notice, it
is the lens.

When a seat wants to change the method to fit its lens, the answer is almost
always that it wants a lens and has reached for the method by mistake.

## Where it came from

Named in the discussion that produced `an-architect-names-its-principles`,
when the question was whether a lens for architecture tensions belonged in
`retro-4ls` or in the architect skill. The seat owns the lens of both the
retro and the test, and that is why the lens for architecture principles is
written in the architect skill and not in the skill that owns the method.
