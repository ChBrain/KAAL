## Want

- Version: 0.0.1, the version `package.json` has carried since
  `the-engine-is-installable`
- Target: `github.com/ChBrain/KAAL`, the annotated tag `v0.0.1`
  (production: yes; it is the only target, it is public, and a consumer
  reads it)
- Artefact: the tag itself, pointing at `293579c`, the commit that merged
  `the-tag-installs-offline`. Nothing is built and nothing is uploaded: what
  ships is a name for a commit, and npm builds the package from it at
  install time.
- Answering means:
  - `npm install github:ChBrain/KAAL#v0.0.1` into an empty project exits 0
  - it adds exactly one package
  - `node_modules/.bin/kaal` prints the usage line and exits 1
  - what it installed holds `bin/` and nothing of the league's working
- Rollback: `git push origin :refs/tags/v0.0.1`, which restores the state
  before this release: no version of this tool is named, and a consumer
  pinning `#v0.0.1` fails to resolve rather than resolving to something
  wrong. Nothing else in the tree moves, because nothing else moved.
- Key: Kai, 7 September 2026, "cut it", for this version and this target,
  in the conversation that carried the board green on `293579c` four jobs
  across two platforms. It is the first use of the `deployment` entry of
  `human.gates` in `kaal.config.json`.

## Proof

- Deploy tests: none, and the reason is a finding rather than a shortcut.
  This skill asks for a deploy script with unit tests because a deploy that
  is only a shell history is a story. Here the whole artefact is a git ref
  and the deploy is `git tag` and `git push`; a script would be a wrapper
  around one command that has never shipped anything, and its tests would
  test the wrapper. The two commands are recorded in this file verbatim,
  and the proof of arrival is the smoke below, run against the tag as a
  consumer meets it. The gap goes to the analyst against `operate`.
- Rollback rehearsed: yes, on a bare clone rather than the remote, since
  rehearsing on the remote is the production target. The tag was created
  there, an install from it answered, the tag was deleted, and an install
  from it then failed to resolve. Recorded below as a run.
- Shipped: not shipped. The tag exists locally on `293579c` and the push to
  the remote is refused. Four attempts, 7 September 2026 around 17:12 UTC,
  with backoff:

  ```
  git push origin v0.0.1
  send-pack: unexpected disconnect while reading sideband packet
  fatal: the remote end hung up unexpectedly

  git push origin refs/tags/v0.0.1:refs/tags/v0.0.1
  error: RPC failed; HTTP 403 curl 22 The requested URL returned error: 403
  ```

  The explicit refspec is what named the cause: a 403, which the plain form
  masks as a disconnect. Branch pushes from this session succeed and have
  all day, and `git ls-remote --tags origin` returns nothing, so the
  remote holds no tag and this is a permission on tag refs rather than a
  transport fault or a state this release left behind. The agent proxy
  reports itself healthy with no relay failures. No tool available to this
  session creates a tag or a ref.

- Smoke: not run. Nothing shipped, so there is nothing to smoke, and a
  smoke against a tag that does not exist would be a story.
- Rollback executed: no, and none is needed. The remote is exactly as it
  was before this release began, which the rehearsal above establishes is
  the honest pre-release state.
