# Plan: 0.0.2

The first plan in this tree, and the first artefact of the manager's seat. It
orders work across the seats and writes none of it: every item names the seat
whose diff it is, and a plan that says what somebody else must do is still a
plan and never their diff.

## The promise

0.0.1 published `@chbrain/kaal` with `files: ["bin"]`, so what a consumer
installs is the deterministic command surface alone. The package is the
primary one and carries everything an embedded consumer needs, which is the
tool and the skills and the agents together; sub packages are carved out
later, when a piece demonstrably travels on its own, and a consumer who takes
one is choosing to take less rather than being asked to assemble more.

So 0.0.2 promises two things a reader can check. Install the package and you
have the method, not a quarter of it. And open any seat's lane and you can
read what it needs from which other seat before it can move.

## The delta

Measured on merged main, not assumed.

- Fourteen walls green, none failing, none waived. Pins: 90 current, 0
  review-needed, 4 reviewed-no-impact, 5 updated.
- Coverage: analyst 64 of 64, architect 58 of 64, tester 58 of 64.
- Five tasks owe a run record. Four are stale because their suite moved
  underneath them, and one has never been recorded at all:
  `an-install-carries-the-method`, which is this release's own promise sitting
  unproved on a green board.
- A sixth, `push-v1`, is red on criterion 7, which wants a move at the skill
  rung with fresh pass records from two models and finds no move at all. It
  reads `not delivered`, which is the tree telling the truth, and it does not
  block this release. `kaal runs` called it green, because that command reads
  records only and hands `verdict` a hardcoded pass and fail so it can borrow
  a message written for a caller that had run the suite.
- No seat can say what it needs from another seat. The trace graph carries the
  architect's dependency on the analyst 118 times over and says nothing about
  the developer, the tester or the operator, whose trees declare either
  nothing or a parent inside their own tree. So a seat that is blocked has
  nowhere to say so and the manager has nothing to read.
- Nothing in the tree can see the registry scope, the publish credential, or
  the repository's merge protections, and `public-v1`'s Handoff has been
  carrying a list of them, unread by any wall, since it was written.

## What a seat needs from a seat

The table is doctrine and belongs in `AGENTS.md`: it is the same on every
task, it names the only question one seat may put to another, and it is what
keeps an ask inside a lane instead of becoming an edit in someone else's
tree. What changes per task is which of these edges is live, and that is what
a seat's own plan records.

| seat      | needs from | the question                                                |
| --------- | ---------- | ----------------------------------------------------------- |
| analyst   | tester     | is this testable, and what would the red test assert        |
| analyst   | architect  | can you architect it in the structure we have               |
| architect | analyst    | is this what the criterion means, and may I propose another |
| architect | tester     | can this seam be proved on its own                          |
| architect | developer  | can you build this on the tree as it stands                 |
| developer | tester     | is there a red test to turn green                           |
| developer | architect  | am I inside the agreed structure                            |
| tester    | analyst    | which criterion does this prove                             |
| tester    | architect  | which seams are separable                                   |
| tester    | developer  | is it built and reachable                                   |
| tester    | operator   | will it run where it ships                                  |
| operator  | tester     | is it proved, on record                                     |
| operator  | architect  | what shape ships                                            |
| operator  | developer  | what is the surface, and did it move                        |
| any seat  | manager    | give my lane attention now                                  |
| manager   | every seat | your clear set and your blocked set                         |

Fourteen edges between the five working seats out of a possible twenty, plus
five to the manager and five back. A graph that dense orders nothing by
itself, which is the point: the table is the vocabulary and the live blocks
are the data.

Three currencies, and a plan that flattens them cannot be prioritised
against, because the remedies differ by an order of magnitude each. An answer
costs a reading. An artefact costs a task in another lane. Attention costs a
session of the only person who has any.

control has not read the delta, it has read the tree.

## The cost, said plainly

Items 2 through 7 are the manage skill and they are six to eight diffs.
Items 1 and 8 through 12 are five. The skill roughly doubles what is left
before the tag, and it is in this release because a release that ships the
method should ship the part of the method that says who asks whom.

release's own promise is on the board for the first time. That is the same
shape as last time. The item nobody found interesting is the one that found
