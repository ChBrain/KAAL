# Plan: 0.0.2

The first plan in this tree, and the first artefact of the manager's seat. It
orders work across the seats and writes none of it: every item names the seat
whose diff it is, and a plan that says what somebody else must do is still a
plan and never their diff.

## The promise

0.0.1 published `@chbrain/kaal` with `files: ["bin"]`, so what a consumer
installs is the deterministic command surface alone. The package is the
primary one and carries everything an embedded consumer needs, which is the
tool and the skills and the agents together; sub packages are carved out
later, when a piece demonstrably travels on its own, and a consumer who takes
one is choosing to take less rather than being asked to assemble more.

So 0.0.2 promises three things a reader can check. Install the package and
you have the method, not a quarter of it. Open `tests/` and you find the whole
of it, five kinds, with every case sitting in the lane of the seat that owns
what it proves. And open any seat's lane and you can read what it needs from
which other seat before it can move.

## What a seat needs from a seat

The table is doctrine and belongs in `AGENTS.md`: it is the same on every
task, it names the only question one seat may put to another, and it is what
keeps an ask inside a lane instead of becoming an edit in someone else's
tree. What changes per task is which of these edges is live, and that is what
a seat's own plan records.

Each seat's work exists only when a specific upstream artefact is in a
specific state, and is blocked by a state it cannot change itself.

| seat      | work exists when                                                 | blocked when                                             |
| --------- | ---------------------------------------------------------------- | -------------------------------------------------------- |
| analyst   | an ask has no requirement, or a closed criterion is contradicted | only a person can answer                                 |
| architect | a requirement has no drawing                                     | the criterion cannot be drawn as written                 |
| developer | a test is red                                                    | the red test needs a seam that does not exist            |
| tester    | a criterion has no proof, or a proof has no fresh record         | a verify or validate fails for a reason outside `tests/` |
| operator  | something is proved and unshipped                                | a control outside the tree                               |
| manager   | two seats are clear and the order is not obvious                 | never on its own account                                 |

The manager cannot be blocked by a seat, only by proxy, carrying somebody
else's block. That is why it is the seat that picks blocks up, and it is the
argument against seats handing work to each other directly.

Three rules hold the whole of it:

- **A seat names the block and never the fix.** The blocked seat says where,
  the manager says when, the owning seat says what. None of the three may
  decide for another, which is why neither a block nor the manager's pick-up
  carries a field for a remedy.
- **A refusal is a block.** Every time a seat tries to write outside its lane,
  that is the moment to record one, and the wall that refuses it already knows
  which seat owns the path.
- **A bug blocks its retest.** A failing verify or validate is recorded as a
  bug naming the earliest of requirements, architecture, code or operations
  where it can be fixed, and the case it blocks is not retested until it
  clears.

## The cost, said plainly

Counted as diffs rather than items, because an item that runs a requirement
through a drawing and a build and a record is four. Items 1 to 3, the test
tree and the move, are about six. Items 4 to 6, the regression plan, the bugs
and the refusal, are about four each. Items 7 to 9, the table and the skill
and six seats writing their first plan, are about fifteen. Items 10 to 14 are
five. So around thirty five, where today landed six.

The order doubled between the last revision of this file and this one, and it
is written here rather than hidden in the items because a plan that grows
quietly is a plan nobody can refuse.

## Verdict

Blocked, on item 1, which is the architect's and has nothing in front of it.

The order doubled and the asker's reason is the criterion rather than a
preference: a glob matches whatever is there, a named reference has an owner,
and a case with no owning lane has nowhere valid to be declared. So the suite
layer is not a fifth document kind for its own sake, it is what makes a lane
true of a test case. Without it, this release ships a method whose own proofs
sit in the wrong seats.

Read: the board, the coverage rows, the delivery report, the trace counts,
`tests/strategy.md`, and `public-v1`'s Handoff.
