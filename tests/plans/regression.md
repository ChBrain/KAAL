# Test plan: regression

## Wall

- Wall: regression

What this plan proves is that a promise this tree has already made still holds. It is a selection and not all of it: every other plan asks whether the work of today is right, and this one asks whether the work of every day before it still is. A regression is a promise that used to hold and stopped, so what it re-runs is the set of promises and not the set of tests.

## Suites

It uses the `acceptance` suite, which the acceptance plan also uses. That is the many to many the suite layer declared and this is its first instance: a suite named by two plans is a finding in neither direction, and what each plan reaches takes nothing away from the other.

Why that one and not the other two. An acceptance case is a criterion a closed requirement states, which is the shape of a promise to whoever installs this engine: a command, a file, a page and what each answers. A contract is a promise between two seams and a unit is a promise a module makes below every seam, and both are how the thing is built rather than what it does. A rebuild that keeps every criterion true and moves every seam under it has broken nothing a consumer can name, and a regression wall that called that a regression would be a wall about the shape of the code.

This is a first selection and not a settled one. When the release and regression split is built, this plan is the half that must stay green while the other half may be red, and a criterion that is changed rather than added leaves this plan rather than staying in it.

## Cases

A case is a named test inside a suite. This plan names none of them: naming suites keeps the selection short and takes whatever the suite later gains, and naming cases would make it exact and stale on the day a suite grows. The cases this plan reaches are answered by the board, each by its path, so what is protected is readable without opening three pages in turn.
